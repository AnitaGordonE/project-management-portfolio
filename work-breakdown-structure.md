# Work Breakdown Structure (WBS)

**Project:** Digital Product Launch | **Version:** 1.0

The WBS decomposes the project into deliverables and work packages. The numbered structure can be used to assign owners, estimate effort and monitor completion.

| WBS ID | Work package | Key activities / output | Suggested owner |
|---|---|---|---|
| 1.0 | Project management | Integrated plan, governance, reporting, RAID and change control | Project Manager |
| 1.1 | Initiation | Charter, objectives, stakeholders, kickoff | Project Manager |
| 1.2 | Planning | Scope baseline, schedule, resource plan, communications | Project Manager |
| 2.0 | Discovery & requirements | Validated business and user needs | Product Manager / BA |
| 2.1 | Stakeholder discovery | Interviews, workshops, process review | BA |
| 2.2 | Requirements | BRD/PRD, user stories, acceptance criteria | Product Manager / BA |
| 2.3 | Prioritisation | MVP backlog and approval | Product Manager |
| 3.0 | UX/UI design | Approved designs and hand-off | Design Lead |
| 3.1 | User flows | Journey maps and wireframes | UX Designer |
| 3.2 | UI design | High-fidelity screens and design system | UI Designer |
| 3.3 | Design approval | Review, revisions and sign-off | Product Manager |
| 4.0 | Development | Working MVP | Engineering Lead |
| 4.1 | Technical planning | Architecture, environment and sprint plan | Engineering Lead |
| 4.2 | Build | Front-end and back-end implementation | Engineering |
| 4.3 | Integration | APIs and third-party integration, if applicable | Engineering |
| 4.4 | Code review | Peer review and build readiness | Engineering Lead |
| 5.0 | Quality assurance | Tested release candidate | QA Lead |
| 5.1 | Test planning | Test strategy, scenarios and test data | QA |
| 5.2 | System testing | Functional, regression and integration testing | QA |
| 5.3 | Defect resolution | Triage, fixes and retesting | Engineering / QA |
| 5.4 | UAT | Business validation and sign-off | Business Owner |
| 6.0 | Launch readiness | Operationally ready launch | Operations Lead |
| 6.1 | Support readiness | FAQs, support workflow and escalation | Operations |
| 6.2 | Communications | Launch content and stakeholder notices | Marketing |
| 6.3 | Go/no-go | Readiness review and decision | Sponsor |
| 7.0 | Release & closure | Controlled deployment and review | Project Manager |
| 7.1 | Deployment | Production release and smoke tests | Engineering |
| 7.2 | Hypercare | Monitor, triage and resolve early issues | Product / Ops / Engineering |
| 7.3 | Closure | Handover, lessons learned and closure report | Project Manager |

## WBS control
Each work package should have one accountable owner, a clear completion definition, an estimate, planned dates and linked dependencies. Changes to the approved baseline must follow change control.
